# FastOffload图示方法说明

这张图展示了FastOffload如何根据参数的重要性，让GPU和CPU分工完成模型微调。输入是初始模型W₀和训练数据，输出是微调后的模型W*。核心思路是：重要性较高的参数每步在GPU更新；另一部分参数把梯度传到CPU，经过合并和跨步累积后周期性更新。这样可以减少GPU需要长期保存的累积数据，并让CPU更新与GPU训练尽量同时进行。

## 1. 根据权重变化划分A、B、C

图左上角是Importance selection。首先，从训练数据中取出若干批次，对初始模型W₀进行Warm-up，得到预热后的模型Ww。随后比较Ww与W₀的权重变化。对于二维权重矩阵，将每一列中各个位置的绝对变化量相加，作为这一列的重要性分数，再按分数排序。

排序后的参数列分成三组：蓝色A表示重要性最高的一部分，橙色B表示接下来的一部分，绿色C表示其余部分。这不是把模型按网络层切成三段，而是给权重中的不同列安排不同的更新方式。

左下角的Weight gradients说明了三组梯度的计算频率。模型始终执行完整的Forward，模型权重采用BF16；普通步主要计算A和B对应的权重梯度，每隔N步再计算一次包含C的完整权重梯度。这里减少的是部分权重梯度的计算，不是跳过模型的前向或切断输入梯度传播。

## 2. A在GPU上每步更新

图中间上方的蓝色路线对应A。各GPU处理不同的训练样本，因此会得到各自的A梯度。通过GPU Reduce-scatter，这些梯度先合并、取平均，再按负责范围分给各张GPU。图中的Aᵣ表示第r个GPU负责的那部分A梯度。

随后，GPU Adam直接更新这部分参数，每个成功训练步都执行一次。更新后的A权重进入右侧的All-gather流程，让其他GPU也获得相应的更新结果。A不需要等待B、C凑满一个周期，因此重要性较高的参数能够持续跟随每步训练调整。

## 3. B在CPU合并并跨步累积，C只在周期边界更新

橙色路线对应B。每张GPU先把自己算出的Local B梯度按层或分块整理成连续数据，图中的L1、L2等表示这些打包后的块。通过Packed transfer，B梯度以BF16从GPU传到CPU。这里传下去的B还没有经过GPU Reduce-scatter。

接着，不同CPU ranks之间执行Reduce-scatter：合并各张GPU对应的B梯度并取平均，每个CPU只留下自己负责的一份，也就是图中的Bᵣ。之后进行Gradient accumulation，把本步梯度加到之前保存的结果上。CPU不必保存N份历史梯度，只需维护一份不断累加的结果；这份结果留在CPU，不需要每步搬回GPU。

到第N个成功步时，当前步的B梯度也加入累积。采用平均方式更新时，将累积结果除以N，再交给CPU Adam。也就是说，B使用整个周期的平均梯度执行一次更新，而不是连续执行N次Adam更新。

绿色路线对应C。C不做跨步累积，只在每隔N步的边界计算梯度。这些梯度先在GPU完成Reduce-scatter，得到各张GPU负责的Cᵣ，再传到CPU。CPU Adam在同一周期更新任务中，分别使用B的平均梯度和C的当前边界梯度更新对应参数；不是把B、C两组梯度相加。B、C的主权重和Adam状态保存在CPU，并使用FP32完成更新。

## 4. CPU更新与GPU训练重叠进行

中间下方的CPU asynchronous pipeline和底部时间轴展示了两侧如何同时工作。一个周期内，GPU持续进行训练，CPU接收B梯度、执行Reduce-scatter并累加。到达周期边界后，CPU启动B、C的Adam更新，而GPU可以继续后续训练，不必每次都停下来等待整个CPU流程结束。

为了避免下一周期覆盖上一周期的数据，需要把已提交更新的数据与正在累积的数据分开保存，并为更新任务记录版本。CPU处理旧版本时，另一块缓冲可以接收新周期的B梯度。如果CPU来不及处理、可用缓冲或允许滞后达到上限，GPU仍然需要等待。因此，时间轴表达的是可以重叠的执行关系，不表示CPU一定能在某个固定步数内完成更新。

## 5. 传回并按顺序发布更新权重

CPU Adam完成后，通过H2D把更新后的B、C参数值传回GPU。传回的是权重，不是累积梯度，也不需要把CPU上的全部Adam状态搬回GPU。随后，通过All-gather汇集各张GPU负责的更新权重，使各GPU上的模型副本保持一致。

右上角的“B/C in order”强调版本顺序：版本v的结果应先于v+1发布，不能让旧结果覆盖新结果，也不能让不同GPU使用不同的已发布版本。相关传输和All-gather完成后，在允许的Forward边界使用新权重，而不是在一次Forward进行到一半时随意替换。经过多个训练周期，最终得到微调模型W*。

> 实现状态：现已提供B CPU Reduce-scatter与CPU累积的可选路径，并通过小模型双GPU测试。首版B下传和CPU归约同步执行，CPUAdam异步；Native密集通信布局仍保留零B占位。图中更充分的通信重叠仍需优化。历史主实验使用GPU B归约/累积，不能作为新路径的性能证据；大模型吞吐与显存收益仍需实测。
